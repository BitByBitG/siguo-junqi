## 2.3 加密聊天、对局与图床

远程浏览器必须使用 **HTTPS 域名**；`http://localhost:3000` 可用于本机测试，`http://局域网IP:3000` 不支持浏览器加密功能。Cloudflare Tunnel 的本地源站仍可配置 `http://localhost:3000`。

浏览器每次建立通道时生成不可导出的 RSA-OAEP 3072 位私钥，服务器用对应公钥封装随机 AES-256-GCM 通道密钥。聊天、图片上传/下载、后台请求和对局操作均使用该密钥加密；上传内容、登录口令和 admin key 都包含在加密请求体内。每条消息使用随机 96 位 IV、128 位认证标签、方向区分的附加认证数据、随机请求编号及时间窗口，拒绝篡改和重放。通道不代替账号认证，每次操作及发送私有状态仍检查登录权限。

- 大厅聊天仅已登录账号接收；后台正确输入 admin key 后可以查看、撤回和禁言。
- 房间聊天、棋盘状态、棋谱和房间图片必须先登录并进入对应房间。暗子仍由服务端过滤，解密不会获得对手暗子。
- 在聊天输入框中粘贴图片，会出现待发送缩略图，可以移除；点击发送或 Ctrl+Enter 才上传并插入 Markdown。每次最多 4 张，单张最大 8 MiB，支持 PNG/JPEG/GIF/WebP。
- 图片原始字节默认保存在 **`/mnt/e/pictures`**，对应 Windows 的 `E:\pictures`。可用 `SIGUO_PICTURES_DIR` 覆盖；首次上传创建目录，需要 WSL 用户有写权限。
- 仅管理该目录的 `siguo-<UUID>.img` 与 `siguo-images.json`。文件内容是原图，`.img` 是内部命名；不会删除该目录其他文件。总容量默认最多 **1 GiB（1,073,741,824 字节）**，超限按上传顺序删除最早图片，不按浏览次数续期。被清理的旧引用会显示图片已过期。可用 `SIGUO_PICTURES_LIMIT_BYTES` 下调上限。
- 图床文件和索引要一起备份；房间关闭后其中图片不可再经该房间读取，文件按容量策略清理。
- 第三方图床链接不能由本站保证加密，聊天中改为外部链接，不自动加载；粘贴上传到本站的图片直接显示。
- BOT 托管源码上限改为 **1 MiB，按 UTF-8 字节计**。外部 BOT 必须升级到本版加密客户端；网站托管程序无需修改。

这保护网络传输以及未授权访问，不提供服务器磁盘加密，也不能阻止有查看权限的人保存或截图。网站代码、服务器和终端仍需可信，HTTPS 不能关闭；系统时间需准确。没有使用所有用户共享的固定解密口令，也没有把密钥放进图片链接。

更新时保留原 `node_modules` 和 `~/.siguo-junqi` 数据目录，覆盖程序文件后重启服务器，浏览器刷新并重新登录。图片目录应独立于代码更新目录保留。

## 2.1 网站托管 BOT

BOT 账号现在可以在首页登录，自动进入 `/bot-studio.html` 工作台。粘贴自己的纯 JavaScript 程序，再点击「保存并启动」，网站服务器会代为运行。退出登录后继续运行，点击「停止托管」才停止。

房主进入普通对局，在左侧「添加 BOT 账号」独立面板选择空位和账号。没有空位时先离座或踢人；排位房不允许 BOT。BOT 工作台、接入说明和管理等页面已加宽。

托管程序用 `function act(state)` 返回动作，可返回 `memory` 保留最多 16 KB JSON 记忆。每次在新的 QuickJS WebAssembly 实例中执行，不提供文件、网络、Node.js 或系统命令。JS 堆限制 48 MB，WASM 内存硬上限 64 MB，另有计算中断及 Worker 超时终止；每步总限时仍为 5 秒。示例搜索使用服务器给出的预算。错误会停止托管，需修复后重新启动。并行上限默认 2，可通过 `BOT_WORKERS` 设置 1–8；共享服务器资源会影响计算速度。

程序与启停状态保存在账号文件同目录的 `bot-programs.json`，可用 `SIGUO_PROGRAMS_FILE` 指定。更新/备份时同时保留它和 `accounts.json`；正在进行的棋局会保存在 rooms.json；程序 memory 不跨服务器重启保存。已启动程序会在网站重启后继续等待新座位。

支持 2／3／4 方真人和外部 BOT 混合对局的网页军棋。房主可以选择 BOT 账号填入空座，或离座后组织纯 BOT 比赛。

## 本版变化

- 新增玩家 / BOT 账号类型，管理员可创建 BOT 账号，注册页也可提交 BOT 账号申请并由管理员审核。
- 原内置 BOT 已拆成 API 客户端；托管程序同样通过该 API 走子，不绕过信息过滤和规则验证。
- 原算法迁移为独立的 `bots/siguo-junqi-bot.mjs`。单独复制这一文件即可运行，通过与其他参赛者相同的 API 认证、布阵、准备和走子，无第三方依赖。
- 房主从已审核 BOT 账号中选择参赛者，同一 BOT 账号可同时占多个位置，各位置独立运行。踢出后棋子原位保留，可由另一账号或真人接替。
- BOT 每步限时 **5 秒**，包含通信时间，超时判负。聊天、心跳不会重置计时；空座保留的军队仍算存活，避免换人时提前结束比赛。
- API 隔离敌方及盟友暗子，公开战斗结果和己方战报。支持版本检查、重复请求幂等与旧座位分配失效。
- BOT 比赛使用普通房间，不计入真人 Rating；目前不包含自动赛程编排或持久化比赛成绩。

## 启动网站

需要 Node.js 18 或以上。首次安装：

```bash
npm ci
npm start
```

打开 `http://localhost:3000`，后台在 `/admin.html`。服务器默认监听 `0.0.0.0:3000`；可通过 `PORT` 改端口。未设置 `ADMIN_KEY` 时首次启动随机生成，保存在账号文件同目录的 `admin-key.txt`；用 `cat ~/.siguo-junqi/admin-key.txt` 查看。已有显式环境变量仍沿用。

本版新增 QuickJS 依赖，更新后需运行一次 `npm install` 再 `npm start`。保留 `node_modules`，无需删除后重装。旧版 `server/bot.js`、`server/strong-bot.js`、`server/bot-worker.js` 已移除，不再加载。

账号默认保存在 `~/.siguo-junqi/accounts.json`，包含密码哈希、注册状态、账号类型和 Rating。可通过 `SIGUO_DATA_DIR` 或 `ACCOUNTS_FILE` 指定位置；更新时保留该数据文件。旧账号自动按玩家账号加载，不需要重新注册。房间与棋局保存在 rooms.json，重启恢复；登录会话重启后失效，需要重新登录。

## 组织 BOT 对局

1. 管理员创建 BOT 账号，或审核注册页的 BOT 申请，将账号密码交给参赛者。
2. 参赛者使用 BOT 账号登录工作台，保存并启动托管程序；也可选择下面的外部客户端方式，二者不能同时走子。
3. 房主创建普通房间，在空座下拉框选择 BOT 账号并添加。列表显示在线与占座状态，可点击刷新。
4. 程序通过 API 布阵、准备。全部准备后，由房主点击开始对局。
5. 纯 BOT 比赛时房主先离座，再给所有位置添加 BOT，自己观战。BOT 被踢出、账号被删除或房间关闭后，旧分配信息不能再提交动作。

WSL / Linux 启动示例：

```bash
export BOT_SERVER='https://你的游戏域名'
export BOT_USERNAME='参赛BOT账号'
read -s -p 'BOT 密码: ' BOT_PASSWORD; export BOT_PASSWORD
node bots/siguo-junqi-bot.mjs
```

如果只下载单文件，在所在目录执行 `node siguo-junqi-bot.mjs`。它无需 `npm install`，默认服务器为 `http://localhost:3000`；每个进程运行一个账号。默认搜索约 3.8 秒并预留网络时间，可用 `BOT_THINK_MS` 调低。

网页接入说明：`/bot-api.html`。网页下载示例：`/downloads/siguo-junqi-bot.mjs`。完整接口说明见 [BOT_API.md](BOT_API.md)。

## API 概览

认证：`POST /api/bot/login`，提交账号密码，后续携带 `Authorization: Bearer TOKEN`。

| 接口 | 用途 |
| --- | --- |
| GET /api/bot/board | 棋盘、棋子种类、特殊铁路和时限 |
| GET /api/bot/session | 查询房主分配的房间和座位 |
| GET /api/bot/rooms/CODE | 读取过滤后的棋局、合法着法与截止时间 |
| POST /api/bot/rooms/CODE/setup | 提交本方全部棋子的位置 |
| POST /api/bot/rooms/CODE/ready | 准备或取消准备 |
| POST /api/bot/rooms/CODE/move | 提交走子 |
| POST /api/bot/rooms/CODE/resign | 认输 |

对局操作均须附带 `assignmentId`、`revision`、`requestId`。可用任意语言实现；建议每 200–500 毫秒轮询。超时不会由服务器代走。

## 保留功能

- 自定义铁路：中央九点、各方第 1／3／5 列贯通、相邻边缘通过角点组成逻辑直道；最后一行不与前方直接铁路相连。
- 2／3 人局不能进入未启用的方向，行营保护、本营锁定、工兵转弯公开、无合法着法困毙判负。
- 落座／离座、观战、房主踢人／关闭房间、对局中原位接替。
- 房间聊天、自己的详细战报、私人粉色标记、白色上一步轨迹。
- 黑灰背景、隐蔽模式、加大的棋子与侧栏。
- 玩家注册审核、改密码、退出登录、管理员账号列表与删除。
- 首页列出所有未关闭房间和规则；公开 Rating 排名。排位房保持原有真人限制。

## 独立 BOT 程序

下载页提供两种单文件程序：`siguo-junqi-bot.mjs` 用于外部 Node.js 运行；`bot-studio-bot.js` 是纯 JavaScript，可直接全选粘贴到 BOT 工作台。两者都采用同一套强化策略：必胜夺旗、敌方本营高概率军旗攻击、本营近距离威胁处理和无意义往返走子惩罚。

## 同一 BOT 账号多座位

同一 BOT 账号可加入多个位置，包括同一房间的多个方向。网站托管会为每个位置独立执行程序，拥有独立 memory 与 5 秒时限；工作台会显示各位置的提交状态。房间左侧账号列表显示“已占 N 位”，不再因已占座而禁用。

若使用外部 `siguo-junqi-bot.mjs`，为每个位置各启动一个进程，并分别设置 `BOT_ASSIGNMENT_ID` 为 `/api/bot/session` 返回的 assignmentId。这样每个进程只控制指定座位。

## 纯 BOT 对局调试观战

当房间全部参赛位置都是 BOT 时，房主可在左侧房主操作区点击「BOT 调试：显示全部棋子」。开启后所有观战者都能看到棋子名称，便于调试 BOT；关闭后立即恢复暗棋。只影响观战网页，不向 BOT API 额外发送任何暗子信息。只要房间不再是全 BOT，显示权限会自动失效。
